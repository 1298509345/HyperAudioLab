# HyperAudio 0.4 日常使用

> 当前体验版为两端0.5，新增项目见 [QUICKSTART-v0.5.md](QUICKSTART-v0.5.md)。下列基本连接、后台设置和快捷入口仍适用。

两端都安装 0.4，AirPods 始终连接 iPhone。使用可信 Wi-Fi 或热点。

## 安装

- 安卓包：`HyperAudioLab-0.4-debug.apk`。与本机生成的 0.3 调试证书一致，可以覆盖本机 0.3；若仍是原 Windows 构建的 0.2，签名不同，需要先导出日志/PCM，再卸载旧版安装并重新配对。
- iOS 包：`HyperAudioReceiver-0.4-signed.ipa`，包含控制中心控件，已签名供本轮登记的 iPhone 开发测试。可用 Xcode / Device Hub 更新现有 App，或在 Xcode 打开 `ios/HyperAudioReceiver.xcodeproj` 运行。主 App 描述文件到期为 2026-11-13 13:02:15（北京时间），到期后需重新签名安装。
- 旧 APK / IPA 保留。当前未连接真机，本轮没有远程更新手机。

## 每次使用

1. AirPods 连接 iPhone，媒体音量先调低。打开 HyperAudio Receiver，默认自动准备接收；也可手动点“开始接收”。首次配对仍要在 iPhone 允许。
2. 安卓点“一键连接并采集”。优先尝试上次设备，失败后再搜索；首次或更换设备时确认选择。
3. 安卓系统采集授权选择“整个屏幕”。本工程只采集音频，不创建或发送屏幕视频；系统撤销授权后必须重新确认。
4. 播放音源，检查 AirPods 有声。可以尝试将 iPhone 锁屏；两端同时锁屏还要求安卓音源自身支持后台播放。锁屏长期稳定性仍需本机型验收。

## 快捷入口

- 安卓：App 中请求添加 HyperAudio 快捷磁贴；也可通过系统快捷设置编辑面板添加。未运行时点击进入连接/授权，运行时点击停止。通知中可暂停声音、恢复、停止，并显示接收设备与运行时长。
- iOS：在控制中心的添加控制界面搜索 HyperAudio，添加“开始接收”和“停止接收”。需要蓝牙媒体输出；系统可能要求解锁，首次网络/配对许可请在 App 内完成。
- iOS 锁屏播放卡片支持暂停、恢复、停止。快捷指令提供开始、停止、一键自检；真实设备上的控制中心与快捷指令执行仍待验收。
- “暂停声音”会保留接收/采集会话；结束本次采集请点击“停止”。安卓暂停仍读取采集器并发送零 PCM，不发送有声音频。停止后不会自动恢复安卓媒体音量，恢复前先暂停音源。

## 后台与网络恢复

安卓“后台设置”中检查通知权限和电池优化，按说明检查 HyperOS 自启动/后台限制。App 保留前台通知和有界续期唤醒锁，但不能保证厂商永不终止它，也不会在系统撤销共享后复用许可。

有效会话中，短暂网络错误会退避重连已配对接收端；iPhone 保留监听并丢弃旧缓冲。iOS 音频中断后只在系统允许、蓝牙路由正常时恢复；否则使用恢复按钮。无音频的长期后台待命不是保证项。

## 一键自检

两端各有“一键自检”，默认不发测试音、不改音量、不请求新配对或采集授权。

- 安卓：检查录音/通知/电池、配对、连接、近期采集电平与包数，以及认证查询到的 iPhone 收包和蓝牙状态。过期指标标记过期，未运行标记未测试。
- iPhone：检查地址、实际监听状态、蓝牙媒体输出、媒体音量、近期收包与 PCM 是否非零，附下一步建议。
- 配对成功不等于有声，收包增长也不等于实际听见。最终请结合 AirPods 听感确认。

## 本轮验收重点

1. 两端依次锁屏，保持音源播放至少一小时；记录中断原因、是否重新授权、耗电。
2. 短暂离开 Wi-Fi / 切换热点后，验证授权仍有效时能恢复，不需要重新首配。
3. 来电中断、AirPods 断开/重连、暂停/恢复和停止，确认声音与界面状态一致。
4. 安卓磁贴、通知操作、iOS 控制中心和锁屏卡片操作，确认能控制同一会话。

构建与自动化检查结果见 `VALIDATION.md`；真机未测试的项目没有按通过记录。
