# 一键连接（Android 0.3 / iOS 0.2）

> 当前日常使用版为两端 0.4，请优先阅读 [QUICKSTART-v0.4.md](QUICKSTART-v0.4.md)。以下保留早期版本步骤。

**日常三步：iPhone 开始接收 → 红米一键连接 → 确认 Android 系统采集授权。** 第一次额外在 iPhone 点“允许”，之后会记住设备，自动处理 IP 和每次变化的 8 位码。

## 安装

Android 新包为 `HyperAudioLab-0.3-debug.apk`，iOS 接收端保持 0.2，协议兼容。本次已确认新旧 APK 调试签名不同，不能直接覆盖；请先导出需要的日志或 PCM，再卸载旧版、安装新版并重新配对。卸载会清除 Android 端配对记录和应用内数据。原 `HyperAudioLab-debug.apk`（0.2）保留用于回退。

Mac 用 Xcode 打开 `ios/HyperAudioReceiver.xcodeproj`，选择 Team 并运行到实际 iPhone；已安装的 iOS 0.2 可继续使用。

## 持续转发

- 系统采集授权选择“整个屏幕”，用于跨 App 切换。本工程只采集音频，不创建或发送屏幕视频。
- Android 0.3 去掉原来的五分钟自动停止，使用界面或前台通知里的“停止”结束。系统撤销授权、采集失败或原有设备/音量保护仍会停止。
- 勾选 PCM 保存时，只保存前五分钟，之后停止存档、继续转发；界面会显示状态。
- 系统播放音频同样需要 MediaProjection 授权和录音权限；没有通过识别前台进程免授权采集的路径。
- 验收时连续播放至少六分钟并切换两个音源 App，检查收包增长、AirPods 有声，再验证手动停止。真机结果以 `VALIDATION.md` 为准。

## 网络和回退

- 同一 Wi-Fi，或者一台开热点、另一台连接它。AirPods 连接 iPhone。
- 允许 iPhone 本地网络权限。建议先保持两端 App 前台，完成已知测试音源验证。
- 本轮联调在关闭 Mac Device Hub 的手机屏幕预览后确认有声；测试时先保持该预览关闭，避免引入调试环境变量。首次无声的唯一原因尚未完全隔离。
- 自动发现约 4 秒。热点屏蔽发现时，会尝试已保存地址和实际热点网关。
- 仍未发现：在红米展开手动面板，只填 iPhone 局域网地址，点“按此地址配对（不用填码）”。
- 也保留“地址 + 当前 8 位码”的完全手动采集按钮。iPhone 的手动信息默认收起。

## 配对故障

- 首次请求有 40 秒读取等待和收端 45 秒总超时；拒绝或取消后可再次连接。
- 配对记录失效：在红米“忘记自动配对记录”，再连接并在 iPhone 允许。iPhone 清除配对需先停止接收。
- 多个接收端时在红米选择；以后优先上次设备。新自动会话会清旧音频连接并自动换码。
- iPhone 已被来电、路由变化或系统停止时，先重新开始接收，再在红米连接。

## 验证范围

Android 构建、Lint 和配对 HMAC 单元测试已通过；另有 TCP 探针和协议测试。2026-11-06 已使用 Xcode 27.2 完成 iOS 真机/模拟器构建、个人开发签名 IPA、真机无线安装和启动；已知 Mac 测试音及红米一键连接采集到 AirPods 的基础播放链路已确认。具体证据和边界见 `VALIDATION.md`。两种热点的普适性、真机续连、后台及异常场景仍需专项测试。

普通应用不能保证小米全机绝对静音。首次配对和音频未加密，仅在可信局域网使用。

## 自动配对控制探针

在电脑项目目录运行：

```sh
python tools/control_probe.py --allow-pairing
```

红米手动面板只填电脑 IP，点“按此地址配对”。该探针显式允许测试期首次配对，终端显示当次 UDP token。之后可以用 `pcm_tool.py listen --token <当前token>` 检查采集。电脑防火墙须允许 TCP 50006 和 UDP 50005。探针不发布 Bonjour，不代表 iOS 接收端或自动发现已通过实测。

探针会在当前目录保存 `control-probe-state.json`，其中含测试配对密钥；请勿公开或提交。关闭探针后不再接受连接。
