HyperAudio 安装与操作手册

交付版本：Android 0.7 / iOS 0.6.9 · 更新日期：2026-11-21

把 Android 正在播放、且允许采集的媒体声音，通过同一局域网传到 iPhone，再用连接 iPhone 的蓝牙耳机收听。耳机不限 AirPods 品牌；仍需系统提供蓝牙媒体输出。

如果下载的是 ZIP，先解压再安装。Android 直接安装 APK。iOS 提供未签名 IPA，首次用自己的 Windows 或 macOS 电脑和 Apple 账户签名安装，无需 TestFlight。

iPhone 导入本机配对文件、登录原签名账户并用 LocalDevVPN 完成首次手动续期后，可以在「快捷指令」中设置手机自动续期。步骤见第 9 节及 SelfRefresh 安装与续期。

1. 先选安装方式

你的情况 使用哪个文件 路线
安装 Android releases/android/HyperAudioLab-0.7.apk 直接打开 APK 安装，见第 3 节
Windows 用户安装 iPhone releases/ios/HyperAudioReceiver-0.6.9-unsigned.ipa 用 Sideloadly 和自己的 Apple 账户签名安装，见第 4 节
macOS 用户安装 iPhone 同一个未签名 IPA，或项目源码 用 Sideloadly 签名安装，或用 Xcode 从源码构建签名，见第 5 节
只排查 Android 问题 releases/android/debug/HyperAudioLab-0.7-debug.apk 调试包，日常优先用上面的优化包

iOS 签名要先理解

发布的 IPA 内含主 App 和控制中心扩展，首次安装时需要用自己的 Apple 账户为两者签名。之后更新或续期沿用同一账户、开发 Team 和 Bundle ID。

免费 Apple 账户的开发描述文件自签发起有效 7 天。付费开发者账户以实际签发的描述文件为准。未签名 IPA 的下载和校验文件见 iOS 0.6.9 发布页。Apple 账户限制

Windows 使用 Sideloadly 签名安装，macOS 还可使用 Xcode 从源码安装。以下 Sideloadly 步骤依据官方资料整理，Windows 端签名安装和扩展控件尚未在本项目完整实测。

2. 准备物品与网络

  • Android 10 或更新系统；本工程 minSdk 29。需要允许录音权限和系统媒体采集授权。
  • 一台 iPhone。本次完整包的快捷控件扩展要求 iOS 18+；本次 SelfRefresh 集成版主 App 最低部署版本为 iOS 17。本轮设备为 iOS 27.2，其他系统组合需实际验证。
  • 可以正常在 iPhone 上播放视频声音的蓝牙耳机，以及一条可传数据的 iPhone 数据线。
  • 首次 iOS 安装需要 Windows 或 macOS、自己的 Apple 账户和可用网络。公司电脑需允许安装相关工具、驱动和连接手机；受管理策略拦截时应联系 IT。
  • 两台手机连同一普通 Wi-Fi，或都连第三台手机开的热点。访客网络或路由器的客户端隔离可能阻止互通。

电脑用于 iOS 首次签名安装，也可在手机续期不可用时重新签名。日常听音只需两端在同一局域网且 App 签名仍有效。

3. Android 安装

  1. 将 releases/android/HyperAudioLab-0.7.apk 传到 Android，例如使用 USB、聊天工具或文件传输工具；无需安装 Android Studio。
  2. 在手机文件管理器中打开 APK。若提示不允许此来源安装，按系统提示仅允许当前文件管理器或下载工具“安装未知应用”。不同 HyperOS 版本入口可能不同。
  3. 点安装或更新。完成后打开 HyperAudio，确认图标与 iOS 的蓝紫色波形一致。
  4. 首次使用时，允许录音及需要的通知权限。录音权限供系统播放音频采集使用，本应用没有读取麦克风录音的采集路径。
  5. 在系统“应用信息／省电策略”中允许后台联网，并根据手机实际菜单设置后台运行或无限制；可在最近任务锁住 App，减少误清理。不要把这理解为系统绝不停止采集的保证。

覆盖安装与旧包

本次 APK 沿用本机 0.3–0.6.1 的测试证书，可直接覆盖对应版本，保留配对和设置。archive/packages/ 中是历史包，不要把旧 debug 包当成当前安装包。

若提示签名冲突，可能旧 App 来自原 Windows 0.2 或其他电脑重新构建的 APK。先确认来源和备份需要的日志／PCM，不要反复安装或直接清数据。卸载会丢本机配对与设置，确需换签名时再卸载重装。安装旧版本还可能遇到系统版本降级限制。

4. Windows：用 Sideloadly 安装 iOS

4.1 安装电脑工具

  1. 打开 Sideloadly 官网，下载适合电脑架构的 Windows 版。不要从不明“代签”网站提交 Apple 账户。
  2. 按该官网当前说明准备 Apple 官网安装版 iTunes 与 iCloud。Sideloadly 当前特别说明其依赖版本与 Microsoft Store 版不同；若已有 Store 版，先阅读官网兼容说明、确认数据后处理版本切换。
  3. 装好后连接 iPhone，解锁手机，确认“信任此电脑”。iTunes 能识别手机后，再开 Sideloadly。能充电不等于数据线可以传数据。

4.2 签名并安装

  1. 把 releases/ios/HyperAudioReceiver-0.6.9-unsigned.ipa 拖入 Sideloadly。
  2. 在设备列表选择真实 iPhone，输入自己的 Apple 账户，使用 Apple ID 签名安装模式；按工具提示自行输入密码及双重认证验证码。
  3. 首次安装可让工具处理可用的 Bundle ID；安装完成后记录所用 Apple 账户和最终 Bundle ID，后续更新／续签应保持一致。原包主标识为 lab.hyperaudio.receiver，扩展为其下的 .controls。
  4. 保留 App 扩展。若高级选项中出现 Remove App Extensions / Plug-ins，需要保留系统快捷控件时不要勾选。不要为安装而随意降低最低系统版本、注入插件或修改网络权限。
  5. 点 Start，等待工具明确提示完成。出错时先保留错误文字再看第 10 节。
  6. 在 iPhone 中开启开发者模式、完成开发者信任，再打开 HyperAudio Receiver，见第 6 节。

关于快捷控件： HyperAudioControls.appex 需要与主 App 一起签名。若签名工具无法保留该扩展，可以用 macOS Xcode 完整安装。

4.3 无线更新与续签

安装后优先按第 9 节配置手机续期。若选择让 Sideloadly 在电脑上无线更新或续期，在 iTunes 的设备同步选项中启用 Wi-Fi 同步，保持两端同网及电脑后台续期组件运行。设备发现失败时可用 USB 安装。

此节工具安装、签名、无线续签及信任流程参考 Sideloadly 官网 和 官方 FAQ。

5. macOS：安装 iOS 的三条路线

5.1 Sideloadly：直接使用 IPA

从 Sideloadly 官网 获取 macOS 版。用数据线连接 iPhone，在 Finder 和手机上完成信任。按第 4.2 节加载未签名 IPA，用自己的 Apple 账户签名安装，并按第 6 节开启开发者模式。

若使用电脑无线续期，在 Finder 的设备「通用」中启用「接入 Wi-Fi 时显示此 iPhone」。手机续期见第 9 节。

5.2 Xcode：从源码完整安装

适合需要完整控件、修改源码或 Sideloadly 签名受阻的人。

  1. 安装能支持目标 iPhone 系统版本的完整 Xcode；仅安装 Command Line Tools 不够。首次打开并完成官方初始化。
  2. 用 Xcode 打开本目录的 ios/HyperAudioReceiver.xcodeproj。
  3. 在 Xcode → Settings → Accounts / Apple Accounts 添加自己的 Apple 账户。网页能登录不代表 Xcode 已成功加载 Team。
  4. 选工程中的 HyperAudioReceiver target → Signing & Capabilities，启用自动签名，选择自己的 Team。对 HyperAudioControls target 也选择同一个 Team。
  5. 若原 Bundle ID 不可用，把主 App 改成自己唯一的标识，例如 com.yourname.hyperaudio.receiver，扩展使用其子标识 com.yourname.hyperaudio.receiver.controls。更新／续签时保持所选标识不变。
  6. 用数据线连接并信任 iPhone，按第 6 节开启开发者模式。新版本 Xcode 在 Device Hub 管理设备；较旧版是 Window → Devices and Simulators。目标必须是在线的真实 iPhone，不能选择 Simulator。
  7. 选择共享 Scheme HyperAudioReceiver，选真实手机，点击运行。等待编译、签名和安装完成；需要时在手机信任开发者。
  8. 打开 App，并检查 iOS 18+ 上的系统快捷控件是否可添加。编译成功、安装成功与实际耳机播放是三项不同验收，听音仍按第 7 节确认。

已有证书时无需重新创建。要手动查看证书，可在 Xcode 账户页选择 Team 后查找 Manage Certificates；没看到该按钮时先确认 Team 已加载。本项目推荐使用自动签名，不要求先手工从网页下载描述文件。免费 Personal Team 的描述文件由 Xcode 管理；到期后重新 Run。

5.3 安装自己已经签名的 IPA

你已签名的 IPA 若在有效期内且包含当前 iPhone，可以用 Device Hub 的 Apps 检查器或 Apple Configurator 安装。手上的文件如果是发布页下载的未签名包，先按第 5.1 节签名。

也可用 devicectl 安装。把尖括号内的内容换成签名后 IPA 的路径和真实设备标识。

DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun devicectl list devices
unzip '<你已签名的IPA路径>' -d /tmp/HyperAudioInstall
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun devicectl device install app \
  --device '<真实iPhone标识>' /tmp/HyperAudioInstall/Payload/HyperAudioReceiver.app

找不到 devicectl 时，先确认完整 Xcode 位于所写的路径。只在本条命令指定 DEVELOPER_DIR，无需为了安装修改全局开发工具设置。

6. iPhone 开发者模式与首次打开

  1. 数据线连接电脑，解锁手机，按提示完成“信任此电脑”。
  2. 打开 设置 → 隐私与安全性 → 开发者模式，开启后按提示重启。重启后解锁，继续确认开启。
  3. 如果没看到开发者模式，先通过安装工具或 Xcode 发起设备准备／配对，再返回设置检查；仅在 Wi-Fi 列表里看到同一网络不等于已完成开发配对。Apple 的具体说明见 开启开发者模式。
  4. 若提示“未受信任的开发者”，到 设置 → 通用 → VPN 与设备管理 → 开发者 App，选择本次签名使用的 Apple 账户，按系统提示信任／验证。
  5. 连接蓝牙耳机，在 iPhone 控制中心确认媒体输出是它；先播放一段相册视频验证耳机有声，再暂停视频。
  6. 打开 HyperAudio Receiver，完成或跳过使用引导，允许需要的本地网络访问。没有弹出权限框时先看 App 状态，不要直接判定授权失败。

开发者模式、电脑信任、开发者 App 信任是不同步骤。不要为此关闭企业安全策略或恢复整台手机。

7. 第一次双机连接与试听

  1. Android 与 iPhone 连接同一可信 Wi-Fi／热点；蓝牙耳机保持连在 iPhone。媒体音量先调低，例如约 20%。
  2. iPhone 打开“连接”页，点 开始接收。如已自动准备接收，则确认页面显示正在等待连接。
  3. Android 打开“连接”页，点 连接并开始。
  4. 首次 iPhone 出现配对请求时，确认是你刚发起的 Android 并允许。之后会记住记录，通常无需再输入地址或码。
  5. Android 出现录音或采集授权时按提示允许。跨 App 长时间使用，系统若提供范围选择，请选 整个屏幕。这个窗口是系统媒体采集授权；本 App 不建立屏幕视频流，也不读取麦克风声音。
  6. 在 Android 打开允许采集的普通视频或音乐。检查 Android 采集电平、iPhone 收包状态，并用耳朵确认蓝牙耳机有声。
  7. 确认 Android 本机没有漏音；屏幕显示媒体音量为零不能单独证明扬声器绝对无声。初次测试可用第三台设备旁听／录音核对。

受保护内容、禁止采集的播放器、电话与语音连麦不作为保证可用范围。不能通过识别前台进程绕过系统采集授权。

自动发现失败时手动连接

先确认 iPhone 还在接收。Android 进入“设备 → 手动连接”；iPhone 在“设备”页找到手动连接信息，使用其当前显示的局域网 IPv4。优先尝试“按地址配对”，首次仍需 iPhone 确认；完全手动模式还需填写 iPhone 当前会话码。重新开始接收后码可能改变，不能一直使用旧码。

已配对但无法恢复时，先停止当前会话，再在两端“设备”中核对／解除对应记录，重新发起。解除某端记录不会自动删除另一端的记录；不要先清空所有设置。

暂停、停止与锁屏

暂停通常保留当前会话；停止结束本端任务。Android 新建采集会话仍需系统授权，系统撤销旧授权后不能自动复用。没有 debug 版固定五分钟断联计时；高级工具中的“保存前五分钟音频”只是 PCM 存档额度，转发仍可继续。

开始播放后可切 App 或锁屏，但 Android／HyperOS 对采集的终止策略及 iOS 后台待命仍由系统决定；遇到系统停止采集需重新授权。本包不承诺永久保活，也不通过一直亮屏来替代后台音频。

快捷开关

Android：到设置的“系统快捷开关”按指引添加 HyperAudio Tile；也可编辑系统快捷面板添加。运行时通知中有暂停／恢复及停止操作。开始新的采集仍可能打开 App 并请求授权。

iPhone：iOS 18+ 在控制中心编辑界面只添加一个“HyperAudio 接收开关”（波形图标）。接收中点按停止，已停止或暂停时点按开始／恢复。0.6.4 起为真正的状态开关：接收开启时亮起，停止或暂停时熄灭；等待 Android 发音频时仍保持开启。App 内开始、停止、暂停和恢复也会请求系统刷新，显示可能略有延迟。首次配对仍需打开 App 确认。正在播放时可使用锁屏播放卡片；快捷指令 App 也可查找 HyperAudio。若重签时移除了控件扩展，控制中心入口将不可用。

从 0.6.3 或更早版本升级时，请先移除旧“接收开关”及独立“停止接收”，再重新添加一个“HyperAudio 接收开关”，以更新系统缓存的控件类型；原“开始／停止接收”快捷指令继续兼容。强制结束 App 后，系统何时刷新已显示的控件由 iOS 调度，不能保证立即熄灭。

声音与睡眠

  • Android 默认优先立体声，连接协商不支持时回退。声音设置在下次连接生效。
  • Android 本机静音方式有媒体音量归零、外接 USB／有线静音负载、媒体静音保护三种。通常先用默认方式；不要在不了解外接设备行为时随意切换。
  • iPhone 有播放模式、本机音频优先与接收音量设置。默认本机音频优先时，来电或本机内容可能打断转发；按页面状态恢复。
  • 耳机断开会触发暂停保护。重新连上后检查系统实际输出，必要时点击恢复，不要在未确认路由时提高音量。
  • 两端睡眠定时各控制本端任务，可选关闭、15／30／60／120 分钟；不等于控制另一台手机的音源。
  • Android 0.7.2 起，停止共享会恢复采集前的媒体音量。睡眠定时到期或外接静音设备断开时保持静音。旧版本需自行恢复音量。

自检、报告与赞助

有声问题先打开“一键自检”，按网络、采集电平、收包、耳机路由和系统音量逐层看。诊断报告由你主动生成并选择保存位置，不自动上传；高级 PCM 可能包含私人声音，不应随意外传。

赞助入口：两端 设置 → 关于与赞助；iOS 再点“查看支付宝收款码”。按原图截图后，可在支付宝“扫一扫 → 相册”识别，由你在支付宝核对收款人、金额并决定是否支付。赞助自愿，不影响 App 功能。

9. 更新、续签与数据保留

Android：优先安装 releases/android/ 中最新优化 APK，保持同一证书。不要用不同电脑随手编译的 debug 包替换日常包；本交付不包含 Android 签名私钥。

iPhone 自动续期

  1. 首次签名安装后，在「设置 → 签名与维护」导入从电脑生成的本机配对文件，并登录首次签名使用的 Apple 账户。
  2. 在 iPhone 安装并连接 LocalDevVPN。首次打开时按系统提示允许添加 VPN 配置。LocalDevVPN 下载
  3. 停止音频接收，回到「签名与维护」，点「验证现有签名」。确认主 App 和控制中心扩展续期成功，并查看新到期时间。
  4. 在 iPhone 上新建快捷指令，依次添加「连接 LocalDevVPN → 刷新应用签名描述文件（HyperAudio）→ 断开 LocalDevVPN」。手动运行成功后，在「快捷指令 → 自动化」设置定时运行这条快捷指令，并选择「立即运行」。

自动化在 iPhone 上执行。到期前在维护页确认新到期时间，VPN 未连接、网络异常或 Apple 要求重新登录时可能续期失败。SelfRefresh 安装与续期

在电脑上更新或补签

若无法安装回环工具，或 App 已过期打不开，用原 Apple 账户、Team 和 Bundle ID 在电脑重新签名覆盖安装。更换签名身份可能影响覆盖安装和配对数据。

10. 常见问题速查

现象 先检查 下一步
Android 签名冲突 旧包来源和证书是否一致 先保存需要的数据，再决定是否换签名重装
Android 切 App 后共享停止 是否授权了单个 App 新建会话时选整个屏幕；若系统已撤销需重新授权

Sideloadly 看不到 iPhone 数据线、解锁、电脑信任、Apple 驱动／Finder识别 先 USB 成功，再配置无线；按官方 FAQ 排查

App ID／免费 App 数量达到上限 Apple 账户已有开发 App 及扩展 查看 Apple 原始限制；等待额度恢复或用自己合适的开发账户

Xcode 一直 Loading teams Xcode 账户页是否真正加载 Team、网络是否可用 记录错误；网页登录成功不等于 Team 可用，避免重复创建证书
Mac 显示已配对但离线 手机解锁、同网、开发模式、信任记录 USB 或重新配对；Mac/iPhone IP 可达还不等于开发通道在线
同网却无法安装／发现 访客隔离、VPN／代理、过滤软件 可对个人代理做临时对照；只放行手机 IPv4 不一定覆盖全部开发流量；企业软件交由 IT 处理
Android 电平始终为零 普通可捕获音源、播放状态、系统采集授权 用高级工具的允许采集测试音源做对照；不要用麦克风冒充系统内录
iPhone 收包增长但无声 实际蓝牙输出、系统媒体音量、暂停／本机优先 先用相册视频确认同一耳机可听，再返回接收页重试
自动找不到但知道 IP 两端处于接收／采集状态、路由器发现限制 使用设备页手动地址配对

本机历史经验：在同一 Wi-Fi 下，IP 和设备端口可达但 Xcode 仍离线；删除 iPhone 的旧开发配对记录再重新配对后恢复。添加 IPv4 白名单后单独重试未恢复。没有完成关闭代理对照，不能据此认定代理为根因。不要一开始就重置整台手机或清理所有网络设置。

Apple 对 VPN／网络过滤影响设备连接的说明见 TN3158。

11. 目录、校验与验证边界

  • releases/：当前 APK／IPA、版本与签名说明；日常安装只看这里。
  • archive/packages/：历史版本和 debug 包，按 Android／iOS 和版本分目录，仅归档。
  • docs/guide/：本手册的 HTML 与 Markdown；HTML 解压后可用浏览器离线阅读、打印或存为 PDF。
  • docs/history/：旧版快速说明，保留当时版本语境。
  • docs/reference/：项目技术说明、协议与研究背景。
  • android/、ios/：当前源码工程；tools/：协议探针和本机验证脚本。
  • validation/：历史及本轮证据。原始日志可能含本地路径、设备或签名元数据，整包适合本人留存／受控交付，不等于脱敏公开发布包。
  • MANIFEST.sha256：交付文件的校验值。ZIP 不包括可重建缓存、IDE用户状态及签名私钥。

本轮会记录 Android 构建／既有单测／lint、iOS 设备与模拟器构建、包版本签名、图标与赞助图一致性。源图片里的二维码能解码不代表已实际支付；本轮不执行付款。Windows重签、不同账户覆盖、各品牌耳机和长时间硬件功耗仍需对应环境实测。更细证据见 validation/VALIDATION.md。

下载后可在解压根目录核对 SHA-256。Android 对照 releases/RELEASES.md，iOS 对照 发布页 的 SHA256SUMS.txt。

Get-FileHash .\releases\android\HyperAudioLab-0.7.apk -Algorithm SHA256
Get-FileHash .\releases\ios\HyperAudioReceiver-0.6.9-unsigned.ipa -Algorithm SHA256

macOS：

shasum -a 256 releases/android/HyperAudioLab-0.7.apk
shasum -a 256 releases/ios/HyperAudioReceiver-0.6.9-unsigned.ipa

隐私说明与锁屏播放

两端在“设置 → 关于与赞助 → 隐私说明”可离线查看完整说明；同文原稿见 docs/guide/隐私说明.txt。内容按当前实现说明采集权限、局域网直传、配对信息、CSV及可选PCM、主动导出、停止清理和赞助。不将配对校验描述为音频加密。

iOS 的锁屏媒体卡片保留播放／暂停，暂停保留接收会话；恢复后接收新音频。完整停止可在 App、控制中心“接收开关”或既有停止快捷指令操作。

两台安卓之间传音频（Android0.7）

两台安装同一APK。B先选“接收”并开始，默认连接耳机；A选“发送”并一键连接B，首次在B允许配对，再在A完成系统采集授权。B播放接收到的音频，不需要屏幕共享或录音权限。A跨App采集仍需选择系统允许的共享范围。

接收默认只向蓝牙媒体、有线或USB耳机播放，没有耳机时等待；用户可主动选择手机扬声器，新的连接恢复耳机默认。暂停保留接收会话，恢复新音频；完整停止后释放会话。同一手机一次只担任一种角色。接收也可用通知/锁屏/单一系统快捷开关控制，实际后台仍受系统和厂商策略限制。

完整流程见 docs/guide/Android双机使用.md；Android0.7隐私说明为 docs/guide/隐私说明-Android-0.7.txt，iOS0.6.6增加签名维护的数据处理说明，见 App 内隐私页。
